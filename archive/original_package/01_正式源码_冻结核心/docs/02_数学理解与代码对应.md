# Delta 形式解释与 DNO 有限代码的关系

## 1. 此文件不是“给一切变化命名”的本体词典

数学表达是从当前观察角度对运行方式做出的压缩。不同角度可以描述同一对象，但不能因为名称出现就强迫系统依照该名称执行。Delta 的抽象价值是：当前结构既是此前改变的结果，也是后续作用的条件；作用可能改变参与者、关联、局部有效规律、观察取向，以及以后何种区别会显现。

## 2. 最少需要写清楚的可执行关系

冻结代码以如下当前有效状态作为数据载体（变量名是实现角色，不是普适定义）：

\[
\Omega_t=(\{(i,x_i,b_i,\ell_i,\mu_i,\tau_i)\}_{i\in I_t},L_t,o_t).
\]

`value=x`、`boundary=b`、`law=ℓ`、`support=μ`、`age=τ`、`links=L`、`observer=o`。保存的是当前张量和当前关联，不保存一个按时间检索的事件文本列表。`ids` 标识当前承载体；`next_id` 仅分配身份号，不是模型学习的“历史记忆”。

唯一共享的数值发生器可用下式理解：

\[
G_\theta(a,b;o,e,\Delta t)=(\delta a,\delta b,c).
\]

- 一个承载体面对第二端为空的情形：`evolve()` 用同一个 `generator` 做局部自主演化。外部输入不是必须的。
- 两个承载体发生实际作用：`compose()` 使用同一生成器更新两端，有时产生新承载体；这一承载体与旧单元采用相同字段，也能继续参与。
- 只在需要时：`propose()` 利用当前有效状态提出寻址分布和活动强度；**提出不等于提交**。
- `attend()` 是主动读取并改变观察取向；自主 `evolve()` 不隐式读取整个关系网络以强制改变其他单元。
- `compact()` 只释放精确零支撑承载体；不能宣称全局最优结构压缩。

这是一个很小的**计算契约**。它可执行、可训练、可反驳，但不穷尽全部 Delta。

## 3. 用户提出的递归公式如何放置，而不是再次机械加入模块

\[
U_{n+1}=U_n\gg(U_n\oplus F(x)+\infty\text{-branch}+\bigtriangledown_{\min}).
\]

它可以从不同观察视角理解为：`U_n` 当前整体；`⊕` 与作用共同形成下一结构；`∞-branch` 表示尚未被预制事件目录完全枚举的潜在后继；`▽min` 暗示无需无止境累加冗余结构；`>>` 暗示当前整体承载实际作用后的有效后果并继续演化。

但**这里没有定义严格代数**：`>>` 不是既定移位运算，`+` 不是张量加法，`∞` 不是无限可枚举计算，`▽min` 也没有指定可适用于所有系统的唯一最小度量。直接将其拆为四个强制执行程序，是把探索性数学理解误认成实现规范。

已有 DNO 的 `value/boundary/law/links/observer` 继续变化，即可构成一种有限可观察的递归；它没有必要拥有一个独立叫“发现规律”的管理器才能形成条件性差异。然而，没有管理器也不代表能在所有未知条件下可靠识别因果规律。

## 4. 状态不是先被语言定义才允许演化

一个原本称为“关系”的第三承载体，可在下一次作用中当作普通承载体；它的局部规律与边界仍继续变化。程序只需要有限、一般的数值合同。身份、关系、边界、区间和历史可以是观察不同因果响应时采用的解释。**观察的区间和结果，是后验研究的描述；不是必须先写成一个开关、规则表和固定阈值。**

同理，“真正有因果作用”在代码层面可以通过控制输入状态、比较反事实输出的差异来测试。但解释测试的不应变成要求模型每次先召开一个外部验证流程才能变化。原计算的数值依赖路径已是可计算的依赖关系，不必再附加一个名叫 Cause 的对象。

## 5. 为什么测试不是最终数学证明

有限的自动测试只是检查有限条件下行为存在、稳定或没有出现某类错误。给出任意有限测试集，总可能存在在集外不同的行为。因此：32项核心测试通过≠开放规律完备；多种随机种子通过≠无限状态可达；对合成规律学会≠自然规律自主推理；当前状态压缩≠绝对无损历史记忆。

开放未知与可执行原语之间是一个真实边界：数学可以允许不封闭的后续解释，但执行程序始终必须有限地表现它。**不因为当前代码无法穷尽无限，就用更多人为事件名来假装已经穷尽。**

## 6. 本次正式封存的修改原则

只保留原冻结核心。原函数名和固定 `d` 是工程选择；不再额外加入多套网络用于宣称“统一性”。新任务可在数据接口外部形成合适的当前单元，但那只是把环境输入送入同一个 DNO，不改变底层生成过程。要判断是否真正擅长某领域，必须训练并与合适基线测试。
